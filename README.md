# Cyber Agent — إيجنت يومي لمحتوى الأمن السيبراني (إنستغرام)

إيجنت يعمل تلقائياً كل يوم عبر **Railway**:
1. يبحث عن أهم خبر/ثغرة سيبرانية (باستخدام Anthropic API + أداة البحث بالويب).
2. يصنّفه ويقيّم أولويته.
3. يكتب محتوى عربي احترافي كامل (عنوان، شرح، تأثير، إجراءات، نصيحة، CTA، هاشتاقات).
4. يصمم 3 صور بهوية بصرية سيبرانية (Modern Minimal، بدون أشخاص).
5. اختيارياً: يرفع الصورة إلى GitHub وينشر المنشور مباشرة على Instagram عبر Meta Graph API.

---

## 0) قبل البدء — الوضع الافتراضي آمن
الإيجنت يعمل افتراضياً في **وضع المراجعة (Dry Run)**: يولّد كل شيء ويحفظه في مجلد
`posts/التاريخ/` بدون أي نشر فعلي. لا يتحول للنشر التلقائي إلا بعد أن تضبط
`AUTO_PUBLISH=true` بنفسك — بعد أن تتأكد من جودة المحتوى والتصاميم لعدة أيام.

## 1) رفع المشروع إلى GitHub

```bash
cd cyber-agent
git init
git add .
git commit -m "Initial commit: cyber security daily agent"
git branch -M main
git remote add origin https://github.com/USERNAME/cyber-agent.git
git push -u origin main
```

> أنشئ المستودع أولاً من github.com (يُفضّل **Private** لأنه سيحتوي لاحقاً على صور
> منشورة، وربما بيانات حسّاسة إن أضفتها بالخطأ — احرص أن يبقى `.env` خارج git كما
> هو محدد في `.gitignore`).

---

## 2) ربط المشروع بـ Railway

1. ادخل إلى https://railway.app → **New Project** → **Deploy from GitHub repo**.
2. اختر مستودع `cyber-agent`.
3. Railway سيقرأ `railway.toml` تلقائياً (Nixpacks + جدولة Cron).
4. في تبويب **Variables**، أضف كل المتغيرات الموجودة في `.env.example` بقيمها
   الحقيقية (لا ترفع ملف `.env` نفسه إلى GitHub أبداً).
5. عدّل `cronSchedule` داخل `railway.toml` إذا أردت وقتاً مختلفاً (الصيغة UTC).
   المثال الحالي `0 2 * * *` = الساعة 6:00 صباحاً بتوقيت الإمارات (UTC+4).

بعد الحفظ، سيقوم Railway بتشغيل `python agent_runner.py` تلقائياً حسب الجدول —
حتى لو جهازك مغلق تماماً.

## 4) تجهيز GitHub Token (لاستضافة الصور فقط)

هذا مطلوب فقط عند تفعيل `AUTO_PUBLISH=true`، لأن Instagram Graph API يحتاج رابط
صورة عام (`image_url`) وقت النشر — نستخدم GitHub نفسه كمستودع صور بدل خادم منفصل.

1. GitHub → Settings → Developer settings → **Personal access tokens (Fine-grained)**.
2. صلاحيات: `Contents: Read and write` على مستودع `cyber-agent` فقط.
3. ضع القيمة في `GITHUB_TOKEN`، واسم المستودع في `GITHUB_REPO` (مثل `username/cyber-agent`).

---

## 5) تجهيز حساب Instagram للنشر (اختياري — فقط لو تريد نشراً تلقائياً كاملاً)

النشر التلقائي على Instagram يتطلب حساب **Instagram Professional (Business/Creator)**
مرتبطاً بصفحة Facebook، وتطبيق Meta. الخطوات:

1. تأكد أن حساب Instagram Professional مرتبط بصفحة Facebook (من إعدادات الحساب).
2. اذهب إلى https://developers.facebook.com → **My Apps** → أنشئ تطبيقاً جديداً
   (نوع Business).
3. أضف منتج **Instagram Graph API** للتطبيق.
4. من Graph API Explorer، ولّد Access Token بصلاحيات:
   `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`.
5. حوّل التوكن إلى **Long-Lived Token** (صالح ~60 يوماً، ويُجدَّد قبل انتهائه):
   ```
   GET https://graph.facebook.com/v20.0/oauth/access_token
     ?grant_type=fb_exchange_token
     &client_id={app-id}
     &client_secret={app-secret}
     &fb_exchange_token={short-lived-token}
   ```
6. استخرج معرّف حساب Instagram Business مرة واحدة:
   ```
   GET https://graph.facebook.com/v20.0/{page-id}?fields=instagram_business_account&access_token={token}
   ```
   الرقم الناتج هو `IG_BUSINESS_ACCOUNT_ID`.
7. ضع التوكن في `IG_ACCESS_TOKEN` والمعرّف في `IG_BUSINESS_ACCOUNT_ID` على Railway.

> ملاحظة: التوكنات طويلة الأمد تنتهي كل ~60 يوماً وتحتاج تجديداً يدوياً أو عبر
> Meta App Review لصلاحيات دائمة أوسع (خارج نطاق هذا الإيجنت البسيط).

## 5.5) (اختياري) تفعيل خلفيات فنية أعلى جودة عبر OpenAI Images API

هذا اختياري بالكامل. بدونه، الإيجنت يعمل ويصمم كل شيء محلياً بـ Pillow مجاناً
كما كان. بتفعيله، يُستخدم OpenAI فقط لتوليد **خلفية فنية بدون أي نص**، ثم
يُضاف النص العربي فوقها بنفس محرك الخطوط الموثوق (لأن نماذج توليد الصور ترتكب
أخطاء إملائية عند كتابة نصوص عربية مباشرة).

⚠️ **مهم جداً:** اشتراك **ChatGPT Plus لا يفيد هنا إطلاقاً** — هو منتج منفصل
تماماً عن OpenAI API من ناحية الفوترة والوصول. تحتاج حساب API مستقل:

1. اذهب إلى **platform.openai.com** (وليس chatgpt.com) وسجّل الدخول/أنشئ حساباً.
2. من القائمة الجانبية: **Billing** → أضف بطاقة ائتمان (أول 5$ عادة مجانية
   لحساب جديد).
3. من القائمة الجانبية: **API keys** → **Create new secret key** → انسخه فوراً
   (يظهر مرة واحدة فقط، يبدأ بـ `sk-...`).
4. في Railway → Variables، أضف:
   ```
   OPENAI_API_KEY=sk-...
   OPENAI_IMAGE_QUALITY=medium
   ```
5. (مستحسن) اضبط سقف إنفاق شهري من **Billing → Limits** لتفادي أي استهلاك غير متوقع.

**التكلفة التقريبية:** صورة واحدة يومياً بجودة `medium` ≈ 0.04-0.07$، أي أقل من
3$ شهرياً تقريباً. إن فشل الاستدعاء لأي سبب (رصيد منتهٍ، خطأ شبكة)، يسجّل
الإيجنت تحذيراً في السجلات ويكمل تلقائياً بالتصميم المحلي المجاني بدل التوقف.

## 5.6) صور إضافية بمقاسات منصات أخرى (LinkedIn وغيرها)

الإيجنت يولّد تلقائياً **3 صور إضافية بمقاس LinkedIn المربع (1080×1080)** لكل
خبر، بجانب صور إنستغرام الثلاث — بنفس المحتوى والهوية البصرية، معاد توزيعها
نسبياً لتناسب المقاس المربع. لا حاجة لأي إعداد إضافي؛ هذا مفعّل افتراضياً.

**للتحكم في المنصات المولَّدة**، أضف متغير بيئة `EXTRA_PLATFORMS` في Railway
(قائمة مفصولة بفواصل):
```
EXTRA_PLATFORMS=linkedin,instagram_square
```
أو لتعطيلها تماماً: `EXTRA_PLATFORMS=` (فارغ).

**المقاسات المتاحة حالياً** (في `PLATFORM_SIZES` داخل `image_generator.py`):

| المفتاح | المقاس | الحالة |
|---|---|---|
| `linkedin` | 1080×1080 (مربع) | ✅ مختبر ويعمل جيداً |
| `instagram_square` | 1080×1080 (مربع) | ✅ مختبر ويعمل جيداً |
| `stories` | 1080×1920 (رأسي طويل) | ✅ مختبر ويعمل جيداً |
| `facebook` | 1200×630 (أفقي) | ⚠️ تجريبي — قد تظهر تداخلات في النص |
| `twitter` | 1200×675 (أفقي) | ⚠️ تجريبي — قد تظهر تداخلات في النص |

المقاسات الأفقية (landscape) لا تزال بحاجة ضبط إضافي للتخطيط (اختلاف نسبة
العرض للارتفاع كبير جداً عن التصميم الأصلي)؛ إن احتجتها فعلياً أخبرني لتحسينها.

**ملاحظة:** قوالب "الخلفية الفنية (OpenAI)" و"التوعية (الأيقونات الثلاث)"
تبقى حالياً بمقاس إنستغرام فقط؛ الصور الإضافية للمنصات الأخرى تستخدم القوالب
الثلاثة الأساسية (القياسي، التحذير، البسيط).

## 5.7) مكتبة الأيقونات — إضافة "مهارة" (أيقونة) جديدة لتصنيف جديد

الإيجنت يختار تلقائياً أيقونة مختلفة داخل الصورة حسب تصنيف الخبر، بدل درع
ثابت للجميع. الأيقونات الحالية المغطاة (13 تصنيفاً، مطابقة لتصنيفاتك الأصلية):

| التصنيف | الأيقونة |
|---|---|
| خبر سيبراني | جرس تنبيه + موجات بث |
| ثغرة أمنية | درع بقفل |
| برمجية خبيثة | حشرة (Bug) |
| Ransomware | مستندات مكدّسة مقفلة |
| حملة تصيد | مغلّف بريد + صنارة صيد |
| تسريب بيانات | قاعدة بيانات + قطرة تسريب |
| تحديث أمني | درع + سهم تحديث دائري |
| نصائح توعوية / أفضل الممارسات | لوحة حافظة بعلامات صح |
| تحليل هجوم | رادار/مسح دائري |
| أدوات جديدة | ترس + مفتاح ربط |
| تقرير استخباراتي | مستند + عدسة تكبير |
| تحذير عاجل | درع (+ شارة تحذير مثلثة في تصميم التحذير تحديداً) |

### لإضافة أيقونة جديدة (مثلاً لتصنيف مستقبلي مثل "هجوم DDoS")

**الخطوة 1 — ارسم الأيقونة:** أضف دالة جديدة في `image_generator.py` (بعد
دوال الأيقونات الحالية، مثل `_bug_icon`)، بنفس التوقيع القياسي:
```python
def _ddos_icon(draw, cx, cy, size, color, width=6):
    """وصف مختصر للأيقونة."""
    # ارسم أشكالاً هندسية بسيطة (خطوط، دوائر، مضلعات) حول (cx, cy)
    # بحجم يتناسب مع size، ولون color، وسماكة خط width.
    # مثال: دائرة بسيطة
    r = size * 0.5
    draw.ellipse([cx - r, cy - r, cx + r, cy + r], outline=color, width=width)
```
كل الأيقونات الحالية أمثلة جاهزة للاقتباس منها (خطوط ودوائر ومضلعات فقط —
بدون صور فوتوغرافية أو أشخاص، التزاماً بالهوية البصرية).

**الخطوة 2 — سجّلها في الخريطة:** أضف سطراً واحداً في `CLASSIFICATION_ICONS`
(بالقرب من نهاية قسم الأيقونات في نفس الملف):
```python
CLASSIFICATION_ICONS = {
    ...
    "هجوم DDoS": _ddos_icon,
}
```

**الخطوة 3 — حدّث تصنيفات `content_generator.py`:** إن كان التصنيف الجديد
غير موجود أصلاً في قائمة التصنيفات المُرسَلة للنموذج (`SYSTEM_PROMPT` في
`content_generator.py`)، أضفه هناك أيضاً ليتمكن Anthropic API من اختياره.

**الخطوة 4:** ارفع `image_generator.py` (و`content_generator.py` إن عدّلته)
لمستودعك، وشغّل المهمة يدوياً للتأكد.

لا حاجة لتعديل أي شيء آخر — أي تصنيف غير مُسجَّل في `CLASSIFICATION_ICONS`
يستخدم تلقائياً أيقونة الدرع الافتراضية بدل أن يتسبب في خطأ.

## 5.8) اختيار الموضوع قبل توليد الصور (لتوفير تكلفة OpenAI)

بدل أن يختار الإيجنت خبراً واحداً تلقائياً ويولّد صوره مباشرة، يمكنك الآن
مراجعة 3 مواضيع مرشحة (نصاً فقط، بدون أي تكلفة صور) واختيار الموضوع الذي
تريده، وعندها فقط تتولّد الصور عبر OpenAI للموضوع المختار حصراً.

### الخطوات

**1. أضف خدمة Railway ثالثة** (بنفس أسلوب خدمة GRC): **New Service → نفس
   المستودع** → غيّر **Start Command** إلى:
```
python propose_topics.py
```
فعّل **Cron Schedule** بوقت مبكر (مثلاً 6:00 صباحاً)، أي قبل ساعتين على الأقل
من جدولة `agent_runner.py` الأساسية، لإعطاء وقت للمراجعة بينهما.

**2. لا حاجة لمتغيرات بيئة إضافية** — تستخدم نفس `ANTHROPIC_API_KEY` و
`GITHUB_REPO` و`GITHUB_TOKEN` الموجودة أصلاً.

**3. راجع المواضيع** من صفحة المراجعة (HTML) → تبويب **"📝 مواضيع مرشحة"**
الجديد. سترى لكل موضوع: التصنيف، العنوان، الملخص، والأفكار البصرية الثلاث
(visual_concepts) المرقّمة [0] [1] [2].

**4. عدّل الفكرة البصرية إن أردت** (اختياري) — افتح ملف الموضوع مباشرة على
GitHub (المسار: `posts/candidates/<اسم الملف>.json`)، عدّل نص أي
`visual_concept` تريد تغييره، واحفظ (Commit) — نفس طريقة تعديل أي ملف على
GitHub التي استخدمتها سابقاً.

**5. اختر الموضوع** — في Railway، على خدمة `agent_runner.py` (الأساسية)،
اضبط:
```
SELECTED_TOPIC_INDEX=0
```
(أو `1` أو `2` حسب الموضوع الذي أعجبك من الثلاثة).

**6. شغّل التوليد** — اضغط **Run Now** على خدمة `agent_runner.py`. سيقرأ
تلقائياً أحدث ملف مواضيع مرشحة، يأخذ الموضوع المختار (بأفكاره البصرية كما
عدّلتها إن عدّلت)، **ويولّد الصور عبر OpenAI لهذا الموضوع فقط** — لا يُنفَق
شيء على المواضيع الأخرى غير المختارة.

### ملاحظات مهمة
- إن لم يوجد أي ملف مواضيع مرشحة (مثلاً لم تُفعّل `propose_topics.py` بعد)،
  يعمل `agent_runner.py` تلقائياً بالطريقة القديمة (يبحث ويكتب خبراً واحداً
  مباشرة) — لا شيء ينكسر، هذه الميزة اختيارية بالكامل.
- إن نسيت تغيير `SELECTED_TOPIC_INDEX`، يُستخدم دائماً الموضوع رقم `0`
  (الأعلى أولوية حسب تقييم Claude) تلقائياً — يبقى النظام يعمل حتى بدون تدخل.
- هذا التدفق مطبَّق حالياً على الأمن السيبراني فقط، ويمكن تعميمه على GRC
  بنفس الأسلوب لاحقاً إن احتجته.

## 6) محتوى GRC (حوكمة، مخاطر، امتثال) — نظام ثانٍ في نفس المستودع

بجانب محتوى الأمن السيبراني، المستودع يحتوي الآن نظاماً ثانياً كاملاً لمحتوى
GRC (Governance, Risk & Compliance)، بهوية بصرية **بيضاء/كريمية رسمية**
(بدل الداكنة السيبرانية)، ومصادر وتصنيفات مختلفة تماماً.

### الملفات الخاصة بـ GRC
```
content_generator_grc.py   البحث + الكتابة (مصادر ISACA, NIST, ISO, GRCI...)
propose_topics_grc.py      اقتراح 3 مواضيع GRC مرشحة (بدون صور)
grc_image_generator.py     التصاميم الثلاثة بالهوية البيضاء الرسمية
agent_runner_grc.py        نقطة التشغيل — يقرأ الموضوع المختار، يرفع لمجلد posts_grc/
```

### إعداد خدمة Railway ثانية (بنفس المستودع)
1. من مشروعك الحالي على Railway → **New Service** → **GitHub Repo** → اختر
   **نفس مستودع** `cyber_agent` (وليس مستودعاً جديداً).
2. من إعدادات الخدمة الجديدة → **Settings** → قسم **Deploy** → غيّر **Custom
   Start Command** إلى:
   ```
   python agent_runner_grc.py
   ```
   (إن كان الحقل يبدو غير قابل للتعديل بسبب `railway.toml`، أنشئ ملف
   `railway.grc.toml` منفصلاً بنفس أسلوب `railway.propose.toml` أدناه، واربطه
   عبر حقل **Config File Path** في إعدادات هذه الخدمة تحديداً).
3. فعّل **Cron Schedule** بالجدول الذي تريده.
4. من تبويب **Variables** لهذه الخدمة تحديداً، أضف نفس متغيرات الخدمة
   الأساسية (`ANTHROPIC_API_KEY`, `GITHUB_REPO`, `GITHUB_TOKEN`,
   `GITHUB_BRANCH`)، بالإضافة إلى:
   ```
   AUTO_PUBLISH_GRC=false       (اتركها false في البداية)
   EXTRA_PLATFORMS_GRC=linkedin
   ```

### اختيار الموضوع قبل توليد الصور (نفس نظام الأمن السيبراني بالضبط)
GRC يدعم الآن نفس تدفق "اقتراح → اختيار → توليد" الموصوف في القسم 5.8 أعلاه:

1. **أضف خدمة Railway ثالثة** (على نفس المستودع) بـ Start Command:
   ```
   python propose_topics_grc.py
   ```
   بجدول Cron مبكر (قبل خدمة `agent_runner_grc.py` بساعتين على الأقل).
   لا حاجة لمتغيرات إضافية — نفس `ANTHROPIC_API_KEY` و`GITHUB_REPO` و`GITHUB_TOKEN`.

2. **راجع واختر** من صفحة المراجعة → تبويب **"📝 مرشحة GRC"** — نفس الآلية
   تماماً: اقرأ المواضيع الثلاثة، اضغط **"✅ اختر هذا الموضوع"** (يحتاج GitHub
   Token بصلاحية كتابة، نفس التوكن المُعَد سابقاً للأمن السيبراني يعمل هنا
   أيضاً لأنه على نفس المستودع).

3. **شغّل التوليد** — اذهب لخدمة `agent_runner_grc.py` → Cron Runs → Run Now.
   سيقرأ تلقائياً اختيارك ويولّد الصور لهذا الموضوع فقط.

بديل يدوي (بدون زر الاختيار): اضبط `SELECTED_TOPIC_INDEX_GRC=0/1/2` في
متغيرات خدمة `agent_runner_grc.py` مباشرة.

إن لم يوجد أي ملف مواضيع مرشحة، يعمل `agent_runner_grc.py` تلقائياً بالطريقة
القديمة (يبحث ويكتب موضوعاً مباشرة) — لا شيء ينكسر.

### المراجعة
افتح صفحة المراجعة (HTML) → التبويبات الأربعة أعلى الصفحة: **🛡️ الأمن
السيبراني**، **📋 GRC**، **📝 مرشحة سيبراني**، **📝 مرشحة GRC**.

### النشر الفعلي على Instagram/LinkedIn (لاحقاً)
`agent_runner_grc.py` يستخدم افتراضياً نفس حساب Instagram المضبوط للأمن
السيبراني (`IG_BUSINESS_ACCOUNT_ID`, `IG_ACCESS_TOKEN`). إن كنت تريد حساب
Instagram منفصلاً لمحتوى GRC، أضف بدلاً منه:
```
IG_BUSINESS_ACCOUNT_ID_GRC=...
IG_ACCESS_TOKEN_GRC=...
```

### حدود حالية
- قوالب GRC البصرية لا تدعم بعد تركيب خلفية فنية خارجية فوقها (بخلاف قوالب
  الأمن السيبراني) — تُستخدم الرسوم المحلية بالهوية البيضاء دائماً؛ الخلفيات
  الفنية من OpenAI تُولَّد (إن فُعِّلت) لكنها غير مُركَّبة على تصاميم GRC بعد.
- تصنيفات GRC الحالية: تحديث تنظيمي، إطار عمل جديد، تقرير وأبحاث، أفضل
  ممارسات حوكمة، إدارة مخاطر، تدقيق وامتثال، فعالية وتدريب، تحذير عاجل —
  لإضافة تصنيف جديد بأيقونة خاصة، أضفه إلى `GRC_CLASSIFICATION_ICONS` في
  `grc_image_generator.py` بنفس أسلوب `CLASSIFICATION_ICONS` الموثّق في
  القسم 5.7 أعلاه.

## حدود ونقاط يجب الانتباه لها
- **لا صور فوتوغرافية لأشخاص**: التصاميم رمزية/تجريدية بالكامل (شبكات، دروع،
  أقفال) تماشياً مع حدود توليد الصور — لا يتم تصوير أشخاص حقيقيين أو تمثيلهم.
- **مراجعة بشرية موصى بها دائماً**: حتى مع `AUTO_PUBLISH=true`، يُفضّل مراجعة أول
  عدة أيام من المخرجات في `posts/` قبل الوثوق الكامل بالنشر الآلي.
- **الثغرات الأمنية**: المحتوى يشرح التأثير والتخفيف فقط، ولا يذكر تفاصيل استغلال.
- **حقوق الملكية**: كل النصوص تُعاد صياغتها؛ لا يُنسخ أي نص حرفي من المصادر.
- **تكلفة API**: كل تشغيل يومي يستهلك طلب Anthropic API واحداً (مع بحث ويب) —
  تحقق من حدود/تكلفة حسابك على console.anthropic.com.
